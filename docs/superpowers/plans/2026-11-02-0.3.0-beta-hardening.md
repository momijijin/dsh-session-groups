# 0.3.0-beta hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the peer-review and release-readiness gaps left after 0.3.0-beta.1 without implementing the deferred tree-rendering redesign.

**Architecture:** Keep the pure model/host boundaries; improve the UI layer incrementally by extracting user-facing components, replacing source-string UI assertions with executable component checks, and adding local CI/quality gates. Publishing assets and live desktop evidence remain user-supplied gates.

**Tech Stack:** Node.js 22, React 18 `createElement`, Cordis 4, esbuild, Playwright, node:test.

**Spec:** `docs/BACKLOG.md` records excluded render work; this plan covers the remaining review findings in the session analysis.

## Global Constraints

- Do not implement R1 lazy collapsed subtrees or R2 flattened virtual tree in this plan.
- Do not change group document schema or host route wire contract.
- Keep data writes restricted to `<dshHome>/storages/dsh-session-groups.json`.
- New dependencies are user-installed; prefer existing tooling.
- Keep 0.3.0-beta compatibility; bump version per landed phase.
- No broad rewrite of drag/drop semantics.

## Review Focus

1. A user with `en` locale sees no Chinese drag labels.
2. A source-only UI test cannot pass while the rendered control is absent or broken.
3. A refactor extracts components without changing drag/drop or search behavior.
4. A clean-profile run never touches the real `~/.dsh`.
5. A release artifact has complete metadata, support entry and verification evidence.
