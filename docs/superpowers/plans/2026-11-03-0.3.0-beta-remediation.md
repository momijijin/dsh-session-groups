# 0.3.0-beta.38 Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) or superpowers:subagent-driven-development (reviewed). Steps use checkbox syntax for tracking.

**Goal:** 把当前分析中确认的 P0/P1 缺陷补齐：配置热生效、危险操作保护、访问门禁一致性、真实交互覆盖和文档真相同步。

**Architecture:** 保持现有洋葱架构。Host 路由从“apply 时快照布尔值”改为“请求时读取配置”；Client 在配置变化后只刷新运行时状态，不重建整个插件。安全加固集中到设置卡、skill repair 路由和 session access 层，不改变 GroupDoc 协议。

**Tech Stack:** Node.js 24, React createElement, DSH Desktop 2.0.18, Cordis 4, esbuild, node:test, Playwright.

**Spec:** 本轮会话内《dsh-session-groups 代码分析报告》+ `README.md` + `docs/ARCHITECTURE.md`。行为契约以当前已安装的 DSH 2.0.18 和现有 375 项测试基线为准。

## Global Constraints

- 版本从 `0.3.0-beta.38` 开始，最终版本由本计划发布任务决定。
- 不新增运行时依赖；不改变 DSH 公共协议。
- 所有新增 UI 继续使用 `Switch` / `Button` / `Tooltip` 等 DSH primitives。
- 保留现有 `session_groups_control` 工具名称、action 名称和 GroupDoc 版本。
- 不删除用户数据；不执行不可逆的外部操作。
- 每个任务必须有独立测试；任务完成后同步 `docs/TEST-RESULTS.md` 或计划勾选状态。
- 默认在实际 `feature/v1.1-session-groups` 分支上内联执行；发布/安装步骤单独确认。

## Review Focus

- 在分组视图打开时切换 `diagnostics` / `debugProbe`，UI 是否立即开始/停止工作，而不是等重启。
- `controlDestructive` 的确认流程是否可被 Escape、外部点击或键盘绕过。
- 用户自己写的同名 `SKILL.md` 是否可能在点击“校验 / 重装”后丢失。
- Fork 在空白、无 access、有 access 三种会话上的显示与成功路径是否一致。
- 文档是否仍声称“不修改标题”“控制路由未挂载”“Pin 可用”等与实现冲突的行为。
